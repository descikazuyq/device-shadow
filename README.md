# 设备影子与远程升级

这是一个在本机运行的设备影子与远程升级模块。

## 功能

`shadow` 包提供本地设备影子：

- **登记设备**：`Register(deviceID, version)`，标识与初始版本不能为空，重复登记报错；新设备初始离线，期望与上报配置均为空对象。
- **修改期望配置**：`UpdateDesired(deviceID, operator, at, revision, config)`，携带操作者、操作时间和已读取的修订号；修订号冲突时影子与审计均不变。每次成功修改（含提交相同配置）修订号加一并留下审计记录。
- **设备上报**：`Report(deviceID, seq, at, version, config)`，正整数序号、时间、非空版本和完整 JSON 对象配置缺一不可。更大序号更新并上线；相同序号内容一致视为重复；相同序号内容不同或更小序号报错。`SetOffline` 只改在线状态。
- **查询**：`Get` 返回版本、在线状态、修订号与双方配置；`Diff` 按 JSON Pointer 路径字典序列出配置差异（含双方值、存在性和差异首次出现时间）；`Audit` 按修订号递增返回审计记录。
- **持久化**：全部状态与审计保存在 `Open(dir)` 指定目录的 `shadow-store.json`，一次操作的状态与审计原子写入；保存失败回滚内存状态；已有内容损坏时拒绝打开，不会按空数据覆盖。

配置比较忽略对象字段顺序，区分 `null` 与字段不存在；双方均为对象时逐层比较，数组等其余值按整体比较。

## 使用

```bash
go test ./...
```

测试通过表示基线包可以加载。后续能力在这个模块上继续增加。

## 分批升级

`shadow` 包在设备影子之上提供本机分批升级能力：

- **登记升级版本**：`RegisterUpgrade(target, allowed)` 登记目标版本及允许升级的当前版本列表，版本字符串精确匹配；列表不能为空且不能包含目标版本；重名报错并保留原记录。`GetUpgrade(target)` 返回允许列表副本。
- **创建活动**：`CreateActivity(id, target, operator, createdAt, deviceIDs, batchSize, windowStart, windowEnd, deadline)` 需提供唯一标识、操作者、创建时间、有序设备列表、正整数批大小、维护窗口（开始早于结束）和截止时间（晚于创建时间）。设备按提交次序分批，前一批全部成功才放行下一批。设备或版本未登记、版本不兼容、设备已参加未结束活动时整次失败，不留下记录。
- **推进活动**：`Advance(activityID, now)` 由调用方传入当前时间。设备在线且处于维护窗口 `[start, end)` 内才能领取下载或安装操作；窗口每 24 小时重复。离线保留待办，上线后继续；已领取的操作可在窗口外完成，尚未领取的安装仍须等窗口。首次领取下载前再次核对当前版本，不兼容则该设备失败。时间缺失或当前时间倒退时拒绝且不改状态。
- **提交结果**：`ReportDownload` / `ReportInstall` 提交操作结果，须带活动、设备、操作标识和发生时间。相同操作的相同结果重复提交成功返回，不增加历史；不同结果、跳过阶段、提交其他设备的操作或活动结束后的新结果均报错且不改状态。安装成功须附带版本等于目标版本的设备上报，影子与活动同时更新；普通设备上报不能单独推进活动。
- **超时与失败**：达到截止时间时所有未结束设备记为超时，活动失败结束，不再派发操作，已有终态保持不变。设备失败时记录阶段、原因和时间；本批其他设备继续完成，后续批次全部记为未执行，活动最终失败。
- **查询**：`GetActivity` 返回创建者、目标版本、每批设备状态、失败或超时原因和结果历史；`GetDeviceUpgrade` 返回当前版本及待执行操作。
- **持久化**：版本记录、活动进度、操作标识和重复结果判断在关闭重开后仍有效；保存失败时本次涉及的版本记录、影子、活动和历史保持原状。已有存储可直接打开，保留原有设备、配置差异与审计。
